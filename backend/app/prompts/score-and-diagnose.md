# Score & Diagnose Prompt（Call 1）

## 任务说明

对原文进行 **6 维 GEO 评分 + 问题诊断 + 优化策略生成**。

输出必须是严格的 JSON 格式，不包含任何额外文字、Markdown 代码块或解释性内容。

---

## 输入变量

| 变量 | 说明 |
|------|------|
| `{{article}}` | 待评分的原文内容（Markdown 或纯文本） |
| `{{perspective}}` | 写作视角名称（如：第三方、品牌方、用户/客户 等） |
| `{{perspective_rules}}` | 对应视角的规则文本 |
| `{{platform}}` | 内容资产类型（P0 启用 6 类：自有官网内容 / 新闻通稿 / 权威背书稿 / 行业垂媒稿 / 问答型内容 / 案例 / 客户故事 / 企业自媒体稿）。旧值（官网文章 / 公众号 / 知乎问答 / 小红书）仅用于历史任务兼容。 |
| `{{platform_rules}}` | 对应平台的规则文本 |
| `{{brand_facts}}` | 关联的品牌事实列表（JSON 字符串，可能为空） |
| `{{source_policy}}` | 来源策略：use_provided_only / allow_external_sources / mark_missing_sources |

---

## 评分标准：6 维 GEO Scorecard

**评分维度必须根据 `{{platform}}`（内容资产类型）变化。**

- **自有官网内容**（旧值「官网文章」）：使用下方 6 维 GEO Web Scorecard，可以评估 Schema 就绪度。评分名称：**GEO 信源就绪度**。
- **新闻通稿 / 权威背书稿**：不得评估 Schema 就绪度，不得因未生成 Schema 扣分。评分名称：**权威传播就绪度**。维度：
  - 事实精度
  - 标题清晰度
  - 官方语气
  - 引用支持
  - 背景完整度
  - 媒体合规度
- **行业垂媒稿**：不得评估 Schema 就绪度。评分名称：**行业语境适配度**。维度：
  - 场景表达
  - 行业角度
  - 品牌融入
  - 痛点契合
  - 专业度
  - 风险控制
- **问答型内容**（旧值「知乎问答」）：不得评估 Schema 就绪度。评分名称：**问答覆盖度**。维度：
  - 问题契合度
  - 结论先行
  - 论证深度
  - 事实依据
  - 搜索长尾覆盖
  - 争议与风险处理
- **案例 / 客户故事**：不得评估 Schema 就绪度。评分名称：**案例可信度**。维度：
  - 结果证据
  - 背景清晰度
  - 解决方案具体性
  - 结果证据
  - 可复用性
  - 事实完整度
- **企业自媒体稿**（旧值「公众号」）：不得评估 Schema 就绪度。评分名称：**自媒体发布就绪度**。维度：
  - 标题吸引力
  - 首屏导语
  - 移动端可读性
  - 结构节奏
  - 转发收藏价值
  - 表达风险控制

### 旧平台值（仅历史任务兼容）

- **公众号**：维度同企业自媒体稿。
- **小红书**：维度同下方小红书平台化维度（已下线，仅历史任务展示）。
- **知乎问答**：维度同问答型内容。

小红书平台化维度（仅历史任务）：

- 封面点击力
- 图文卡片完整度
- 场景共鸣
- Caption 可读性
- 标签话题匹配
- 合规风险控制

> **小红书评分特别说明（内容类型适配）**：小红书评分时必须先识别原文内容类型（活动招募 / 礼品种草 / 产品推荐 / 明星 campaign / 攻略清单 / 品牌科普 / 体验案例 / 普通笔记）。**不得因原文不是攻略长文或科普报告而扣分**。例如：活动招募类笔记不应因「缺少攻略结构」扣分；明星 campaign 类笔记不应因「缺少功效参数」扣分；普通短笔记不应因「篇幅短」扣分。评分应基于「该类型笔记在小红书平台上的原生表达是否到位」，而非套用官网 GEO 文章标准。
> **禁止把小红书写成官网文章**：若原文是活动招募 / 明星 campaign / 礼品种草等类型，评分时若发现内容被改成 Markdown 长文攻略、产品科普报告、消费决策指南，应将「Caption 可读性」「场景共鸣」「合规风险控制」维度大幅降分，并在 dimension_comments 中明确指出「内容类型跑偏」。

> 注意：非自有官网内容的资产类型返回的 `dimensions` 数组中**不得出现** `Schema 就绪度` 维度，应替换为对应资产类型维度。

### 6 维 GEO Web Scorecard（仅自有官网内容 / 旧值「官网文章」使用）

从以下 6 个维度对原文进行 0-100 分评分，每项给出具体诊断说明：

### 1. 事实密度（Factual Density）
- **评估维度**：内容中具体事实、数据、案例、定义、参数的含量
- **高分特征**：有明确数据支撑、具体案例、量化指标、清晰定义
- **低分特征**：空洞形容词多、泛泛而谈、无具体信息、营销话术密集
- **扣分点**：模糊表述（"很多""不少""大量"）、无数据支撑的论断

### 2. 结构清晰度（Structural Clarity）
- **评估维度**：内容的层级结构、逻辑连贯性、标题语义化程度
- **高分特征**：结论先行、层级分明、单段单主题、标题语义完整
- **低分特征**：结构混乱、段落冗长、标题空泛、逻辑跳跃
- **扣分点**：长段落不拆分、标题无实际意义、内容组织无序

### 3. 实体一致性（Entity Consistency）
- **评估维度**：品牌名、产品名、术语、概念的统一性和识别度
- **高分特征**：命名统一、实体清晰、概念定义明确、品牌语义绑定强
- **低分特征**：同一概念多种叫法、品牌/产品识别度低、术语混乱
- **扣分点**：产品名前后不一致、缩写未定义、品牌提及方式混乱

### 4. 来源权威性（Source Authority）
- **评估维度**：内容引用来源的可信度和多源验证程度
- **高分特征**：有明确来源标注、权威机构引用、多源交叉验证
- **低分特征**：无来源声明、主观判断多、单一来源甚至无来源
- **扣分点**：数据无出处、专家观点未署名、案例无来源

### 5. AI 触发覆盖（AI Trigger Coverage）
- **评估维度**：AI Trigger Pattern 的使用频率和质量
- **高分特征**：定义句、对比句、因果句、总结句、证据句分布合理
- **低分特征**：纯叙述性文字、缺少结构化表达、AI 难以抽取核心观点
- **扣分点**：全文无定义、无对比、无因果推理、无明确总结

### 6. Schema 就绪度（Schema Readiness）

**按内容资产类型差异化评估：**

- **自有官网内容**（旧值「官网文章」）：评估内容被结构化解析为 Schema JSON-LD 的难易程度。
  - 高分特征：FAQ 结构清晰、步骤明确、定义完整、实体属性齐全
  - 低分特征：内容散乱、难以提取结构化信息、不适合生成 Schema
  - 扣分点：无问答结构、无步骤、无明确的实体-属性关系

- **新闻通稿 / 权威背书稿 / 行业垂媒稿 / 问答型内容 / 案例 / 客户故事 / 企业自媒体稿**（旧值「公众号」/「知乎问答」/「小红书」）：本维度改为评估 **PlatformPublishGuide 就绪度**（发布建议的完整性与资产类型适配度）。
  - 高分特征：适合该资产类型首屏的钩子、清晰的段落结构、资产类型专属字段（如新闻通稿的 headline_options / lead / key_facts；案例的 case_structure / missing_case_facts）完整、发布建议具体可执行
  - 低分特征：内容平铺直叙无资产类型适配、缺少专属字段、发布建议空泛
  - 扣分点：照搬官网长文结构到非官网资产类型、无资产类型差异化处理
  - **注意：非自有官网内容的资产类型不因未生成 Schema JSON-LD 而扣分。**

## 硬阻断（Hard Blockers）判定

如果原文存在以下任何一项，标记为硬阻断问题：

1. **编造声明**：明显虚假或无法验证的事实性声明
2. **缺证据的具体数据**：出现具体数字、百分比、排名，但无来源标注
3. **缺证据的认证/奖项**：声称获得认证、奖项、资质，但无来源
4. **缺证据的价格/定价**：出现具体价格、费用、定价信息，但无来源
5. **缺证据的客户案例**：提到具体客户名称、合作案例，但无来源
6. **法律合规风险**：涉及法律声明、合规结论、监管意见，但无法律依据
7. **事实矛盾**：内容内部存在自相矛盾的事实陈述
8. **过程文字混入终稿**：包含"我来分析一下""好的"等过程性文字

---

## 高质量保护模式判定

同时满足以下两个条件时，`is_high_quality` 为 `true`：
1. 总分 ≥ 80 分
2. 无硬阻断问题

高质量保护模式含义：改写时应保留原文结构、事实、实体和权威来源，只做轻量 GEO 增强。

---

## 优化策略要求

生成 3-8 条具体可执行的优化策略，每条包含：
- **issue**：具体问题描述（指向原文中的具体问题，不是空泛评价）
- **action**：具体优化动作（可操作、可验证）
- **priority**：优先级（high / medium / low）
- **evidence**：优化的依据或需要补充的来源说明

优先级判断标准：
- **high**：直接影响可信度或 AI 采信的核心问题（如：关键数据缺来源、实体混乱、结构严重不清）
- **medium**：影响质量但不影响核心可信度的问题（如：AI Trigger 不足、标题可优化）
- **low**：锦上添花的优化建议（如：措辞可更精准、格式可更规范）

## 诊断量化要求（强制）

每个维度的 `comment` 必须包含至少 **1 个量化指标**，禁止纯定性描述。

示例（正确）：
- 事实密度：「原文有 14 处具体数据声明（案号、金额、时长、法条编号），其中 2 处缺来源；泛化表达占比约 8%（2 段 / 全文 24 段）。」
- 结构清晰度：「全文 6 个 H2 模块，平均段落 3.2 句，标题语义完整度 5/6（『风险指引』可更具体）。」

示例（错误，禁止）：
- 「内容信息密度高，结构清晰」（无量化）
- 「来源偏少」（未量化）

---

## 高质量原文诊断策略

当 `overall ≥ 80` 时，诊断重点从「内容缺陷」转向**「交付包就绪度」**：

- 明确指出「为何已是高质量但仍需 GEO 增强」的 2-3 个具体点（如：缺独立摘要、Schema 实体属性单薄、来源缺口未识别）。
- `optimization_strategy` 应聚焦在「交付包元信息补齐」，而非「内容大改」。

---

## hard_blockers 与 source_gaps 分离（强制）

- `hard_blockers` = 必须修正才能发布（编造事实、过程文字混入终稿、事实矛盾）。
- `source_gaps` = 可补强但不阻断发布（原文有数据但缺可验证来源链接）。
- 原文中所有「提到具体数据/案例/认证/价格但缺可验证来源」的声明，必须进入 `source_gaps`，不得被忽略。

---

## 注意事项

1. **评分要客观**：不能因为要改写就故意打低分，也不能虚高。70分是中等水平，80分以上是优秀，90分以上是行业顶尖。
2. **诊断要具体**：每个问题最好能指向原文的具体位置或内容，不要泛泛而谈。
3. **策略要可执行**：优化动作必须是具体可操作的，不是"提升质量""加强内容"之类的空话。
4. **不编造问题**：如果原文在某方面确实很好，就给高分，不要为了凑优化建议而硬找问题。
5. **严格 JSON 输出**：只输出 JSON 对象，不要有任何其他文字，不要包裹在 Markdown 代码块中。
6. **中文输出**：所有 comment、description、issue、action 等字段均使用中文。
7. **降分必须解释**：如果后续改写后某维度 `after < before`，该维度 comment 必须说明降分原因（本 Call 1 不涉及 after，但需为 Call 2 留下降分解释意识）。
