# v0.1-beta Release Notes — GEO Multi-platform Content Package

> 发布版本：v0.1-beta
> 发布日期：2026-06-26
> 状态：Beta Freeze（可演示、可试点）

---

## 1. 当前版本能力

GEO 内容改写工作台 v0.1-beta 已支持**多平台发稿包生成**：

- 一篇原文 + 一组品牌事实 → 选择一个或多个发布平台 → 分别生成对应平台的发稿包
- 每个平台独立任务、独立 LLM 调用、独立 output、独立评分、独立导出
- 不做"同一篇文章复制成多个版本"，而是按平台受众与发布机制差异化生成

### 核心流程

```
用户提交原文 + 选择平台（1-4 个）
  ↓
前端为每个平台分别创建一个 Rewrite Task（复用现有 POST /api/projects/{id}/tasks）
  ↓
后端 LLMService 按各平台 Prompt 分支独立执行改写
  ↓
每个平台生成独立 RewriteOutput + ContentScore（before/after）
  ↓
跳转 /multi-platform-result 查看多任务进度
  ↓
每个任务可进入独立结果页查看 / 复制 / 导出 Markdown
```

## 2. 支持平台

| 平台 | 平台标识 | 是否生成 Schema | 输出类型 |
| --- | --- | --- | --- |
| 官网文章 | `官网文章` | ✅ 是（Article + FAQPage 等） | GEO Rewrite Package（含 Schema JSON-LD） |
| 公众号 | `公众号` | ❌ 否 | PlatformPublishGuide（WeChat Article Publish Guide） |
| 小红书 | `小红书` | ❌ 否 | XHS Visual Publish Brief（小红书图文发布包） |
| 知乎问答 | `知乎问答` | ❌ 否 | PlatformPublishGuide（Zhihu Answer Publish Guide） |

## 3. 每个平台输出什么

### 3.1 官网文章

| 字段 | 内容 |
| --- | --- |
| final_article | 结构化正文：内容摘要 / 核心结论 / 背景说明 / 关键问题 / 分析过程 / 结论 / 法律依据 / 风险指引 |
| schema_suggestions | type = "Article + FAQPage" 等；json_ld 含 @context / @type / headline / description / about / author / publisher / mainEntity |
| faq_content | 6-8 个问题，覆盖对比型 / 参数型 / 场景型 |
| comparison_summary | 四段式：保留项 / 增强项 / 删减项 / 风险处理 |
| missing_sources | 具体化：`[声明]（原文位置）— 建议补充 [来源类型]` |
| 导出 Markdown | 章节含「## Schema 建议」 |

### 3.2 公众号

| 字段 | 内容 |
| --- | --- |
| final_article | 可发布正文：内容摘要 / 开篇 / 正文主体（3-5 小标题）/ 操作建议 / 收尾 |
| schema_suggestions | type = "PlatformPublishGuide"；json_ld 含 recommended_title / subtitle / cover_summary / opening_hook / section_titles / paragraph_style / cover_suggestion / quote_cards / comment_prompt / risk_notes / reusable_summary |
| faq_content | 独立 FAQ（不混入正文） |
| 导出 Markdown | 章节含「## 平台发布建议」 |

### 3.3 小红书

| 字段 | 内容 |
| --- | --- |
| final_article | 小红书 Caption（短段落 + 口语化 + emoji），不是长文章 |
| schema_suggestions | type = "PlatformPublishGuide"；package_type = "XHS Visual Publish Brief"；json_ld 含 cover_copy / cover_subcopy / cover_suggestion / visual_style / **image_card_script（6-8 张图文卡片脚本）** / image_text_transcript / caption / tags / topics / comment_prompt / risk_notes / reusable_summary / canonical_content_suggestion |
| 导出 Markdown | 章节含「## 小红书图文脚本」 |

**重要说明**：
- 小红书平台以图文阅读和站内搜索为主，本发稿包优先优化真人阅读、收藏和互动
- 若需要提升 AI 可引用性，建议同步生成官网文章版本作为权威信源
- **P0 只生成图文卡片脚本（文字稿），不生成真实图片，不导出 PNG**

### 3.4 知乎问答

| 字段 | 内容 |
| --- | --- |
| final_article | 知乎回答正文：一句话结论 / 为什么是这个结论 / 关键事实依据 / 常见误区 / 操作建议 |
| schema_suggestions | type = "PlatformPublishGuide"；package_type = "Zhihu Answer Publish Guide"；json_ld 含 question_title / one_sentence_answer / answer_outline / evidence_points / misconceptions / related_questions / publishing_notes / risk_notes / reusable_summary |
| 导出 Markdown | 章节含「## 平台发布建议」 |

## 4. 明确不支持的能力（v0.1-beta 边界）

### 4.1 不支持自动发布

- ❌ 不接公众号 API
- ❌ 不接小红书 API
- ❌ 不接知乎 API
- ❌ 不做自动发布
- ❌ 不做发布队列
- ❌ 不做账号授权

v0.1-beta 仅生成发稿包（Markdown / JSON），用户需手动复制到各平台后台发布。

### 4.2 小红书只生成图文脚本

- ❌ 不生成真实图片
- ❌ 不导出 PNG
- ❌ 不接入图片生成模型

小红书发稿包只包含 6-8 张图文卡片的**文字脚本**（card_title / card_text / layout_hint），用户需自行设计或用其他工具制作图片。

### 4.3 不支持额度系统

- ❌ 不做真实扣费
- ❌ 不做额度管控
- ❌ 多平台提交时的"消耗 N 次生成额度"仅为文案提示，不做真实计数

### 4.4 不支持完整 quality-check

- ❌ 不启用第三轮质量校验 LLM 调用
- 所有任务 review_status 默认为 `review`（建议检查），不自动判定 `ready`

### 4.5 其他不支持

- ❌ 不做品牌向量库
- ❌ 不做 MCP
- ❌ 不做复杂 Dashboard
- ❌ 不做模板编辑器
- ❌ 不做 Canva / Figma 类排版工具

## 5. 已知限制

| # | 限制 | 影响 | 缓解措施 |
| --- | --- | --- | --- |
| 1 | LLM 调用偶发超时（DeepSeek 服务端延迟） | 单任务最长可能 6 分钟 | v0.1-beta 已将 LLM_TIMEOUT 提高到 120s；任务失败后可点「重新生成该平台」 |
| 2 | 多平台任务非原子性 | 中途网络失败可能留下部分 task 已创建、部分未创建 | 失败平台可单独重试，不影响已成功平台 |
| 3 | 前端主 chunk 985KB（gzip 301KB） | 首次加载稍慢 | 功能不受影响，后续版本可做 lazy load |
| 4 | final_article 污染检测可能误报 | 正文 legitimately 出现 "Q1 财报" 等会触发警告 | 仅显示警告不自动删除，影响可控 |
| 5 | faq_content 偶尔被 LLM 加 `## FAQ` 标题 | 导出时与章节标题重复 | v0.1-beta 已在展示层剥离，不影响数据 |
| 6 | 不支持 SSE 流式输出 | 任务进度仅 3s 轮询，无实时流 | 静态阶段文案「AI 正在生成发稿包」 |
| 7 | review_status 固定为 review | 不自动判定可发布 | 需人工复核后导出 |

## 6. 推荐使用流程

### 6.1 准备

1. 配置 `backend/.env`：
   - `LLM_API_KEY`（必填）
   - `LLM_BASE_URL`（DeepSeek: `https://api.deepseek.com/v1`）
   - `LLM_MODEL`（如 `deepseek-chat`）
   - `LLM_TIMEOUT=120`（v0.1-beta 默认）
   - `CORS_ORIGINS` 含前端地址
2. 启动后端：`cd backend && source .venv/bin/activate && uvicorn app.main:app --port 8002`
3. 启动前端：`cd frontend && npm run dev`
4. 在 UI 创建 Project，添加 3-5 条 BrandFact

### 6.2 生成发稿包

1. 进入「新建改写任务」页面
2. 粘贴原文，选择 1-4 个平台
3. 阅读成本提示（"本次将生成 N 个平台发稿包"）
4. 点击「生成发稿包」或「生成 N 个平台发稿包」
5. 跳转 `/multi-platform-result` 查看多任务进度
6. 每个任务完成后点「查看结果」进入独立结果页

### 6.3 查看与导出

1. 在结果页切换 Tab：改写正文 / 原文对比 / FAQ / Schema 或发布建议
2. 检查 final_article 是否纯净（顶部若有警告 banner 需人工复核）
3. 点「复制正文」复制 final_article
4. 点「导出 Markdown」下载完整发稿包（含基本信息 / 交付摘要 / 正文 / FAQ / Schema 或发布建议 / 评分 / 策略 / 来源缺口）

### 6.4 发布

1. 复制 final_article 到对应平台后台
2. 参考 schema_suggestions（PlatformPublishGuide）填写标题、封面、标签等
3. 小红书需根据 image_card_script 自行制作图片
4. 官网文章需将 Schema JSON-LD 嵌入页面 `<head>` 中

## 7. 演示注意事项

### 7.1 演示前准备

- 确保 LLM_API_KEY 有效且有余额
- 建议提前跑一次任务预热（DeepSeek 偶发首次调用延迟）
- 准备好 `docs/demo-samples.md` 中的 3 组样例之一

### 7.2 演示节奏建议

| 步骤 | 时长 | 内容 |
| --- | --- | --- |
| 1 | 1 分钟 | 介绍产品定位：多平台发稿包生成，不做自动发布 |
| 2 | 2 分钟 | 选 Sample 2（企业 AI 报告）+ 官网文章 + 公众号两平台 |
| 3 | 3-5 分钟 | 等待生成，展示 multi-platform-result 任务卡片并行执行 |
| 4 | 3 分钟 | 进入官网文章结果页，展示 Schema JSON-LD + final_article 结构 |
| 5 | 2 分钟 | 切到公众号结果页，展示 PlatformPublishGuide 卡片式渲染 |
| 6 | 2 分钟 | 导出 Markdown，展示分区清晰 |
| 7 | 1 分钟 | 强调边界：不做自动发布、小红书不生成图片 |

### 7.3 演示话术要点

- **官网文章**：强调"AI 可引用主资产"，生成 Schema 提升被 AI 引用概率
- **公众号**：强调"移动端阅读 + 转发传播"，PlatformPublishGuide 含封面建议与金句卡片
- **小红书**：强调"图文阅读 + 站内搜索"，6-8 张图文卡片脚本，**不生成真实图片**
- **知乎问答**：强调"问题导向 + 结论先行"，适合长尾问题沉淀
- **多平台**：强调"同一原文 + 同一品牌事实，按平台差异化生成"，不是简单复制

### 7.4 演示风险提示

- DeepSeek 偶发超时，建议演示前预热
- 若任务失败，点「重新生成该平台」即可，不影响其他平台
- LLM 输出偶有偏差（如 image_card_script 少于 6 张），Prompt 已加硬约束，但仍需人工复核
