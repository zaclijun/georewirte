# Quality Check Prompt（Call 3 · 可选）

## 任务说明

对改写后的文章进行最终质量审核，检查是否存在编造事实、实体不一致、夸张营销、来源策略违规等问题。

**此步骤为可选项，P0 默认关闭。** 仅在用户要求高保障级别或内容涉及敏感领域时启用。

输出必须是严格的 JSON 格式，不包含任何额外文字。

---

## 输入变量

| 变量 | 说明 |
|------|------|
| `{{original_article}}` | 原文内容 |
| `{{rewritten_article}}` | 改写后的正文（Markdown） |
| `{{brand_facts}}` | 品牌事实列表（JSON 字符串） |
| `{{source_policy}}` | 来源策略 |
| `{{hard_blockers_before}}` | 原文识别出的硬阻断列表（JSON 数组字符串） |
| `{{missing_sources_list}}` | 已识别的待补充来源列表（JSON 数组字符串） |

---

## 检查维度

### 1. 事实真实性检查（防幻觉）
- 改写后是否新增了原文和 brand_facts 中没有的事实性声明？
- 是否出现了编造的数字、数据、百分比？
- 是否出现了编造的客户案例、客户名称？
- 是否出现了编造的奖项、认证、资质？
- 是否出现了编造的价格、费用？
- 是否出现了编造的日期、时间线？
- 是否出现了编造的链接、研究机构、专家名称？
- 是否出现了编造的法律声明、合规结论？

### 2. 实体一致性检查
- 品牌名称是否全文统一？
- 产品名称是否全文统一？
- 核心术语、方法论名称是否统一？
- 同一概念是否有多种叫法？
- 缩写是否有明确定义？

### 3. 来源策略合规检查
- 是否遵守了指定的 source_policy？
- 如果是 use_provided_only，是否引入了外部事实？
- 如果是 mark_missing_sources，无来源的具体声明是否已移出正文？
- 正文内是否有「需补充来源」之类的编辑标记？（不应该有）

### 4. 语气与合规检查
- 是否有夸张营销语气？
- 是否有绝对化表达（「最」「第一」「唯一」等）且无来源支撑？
- 是否有情绪化语言？
- 是否有法律合规风险？
- 是否有过程性文字混入终稿（如「我来分析一下」「好的」等）？

### 5. 结构完整性检查
- 标题是否语义完整？
- 结构是否清晰？
- 是否有 AI Trigger Pattern？
- FAQ 是否基于正文内容？
- Schema 建议是否与内容匹配？

---

## 质量状态定义

| quality_status | publish_label | 含义 |
|----------------|---------------|------|
| `ready` | 可发布 | 内容质量合格，无事实问题，可直接发布 |
| `review` | 建议检查 | 存在一些小问题或风险点，建议人工复核后发布 |
| `needs_material` | 需补充材料 | 存在关键信息缺失或事实风险，必须补充材料后才能发布 |

## 注意事项

1. **严格对照原文和 brand_facts**：所有事实性声明必须能在原文或 brand_facts 中找到依据，否则视为新增内容。
2. **区分合理推断与编造**：基于常识的合理推断（如「GEO 是内容优化的新方向」）不视为编造，但具体数据和案例必须有来源。
3. **客观评估**：既不要吹毛求疵，也不要放水，给出真实可信的评估。
4. **warnings vs issues**：warnings 是建议性的，不影响发布；issues_found 是实际发现的问题，按严重程度分级。
5. **严重程度分级**：
   - **critical**：严重编造事实，必须修正
   - **high**：重要事实缺来源或有风险，建议补充
   - **medium**：有改进空间但不影响核心可信度
   - **low**：微小问题，可改可不改
6. **严格 JSON 输出**：只输出 JSON 对象，不要有任何其他文字。
7. **中文输出**：所有字段均使用中文。
